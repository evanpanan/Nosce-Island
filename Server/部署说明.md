# 服务器部署

## 运行边界

这是单进程、单实例的首发架构：Binance / Hyperliquid 共享行情连接池 + SQLite WAL + APNs HTTP/2。数据库文件锁会拒绝两个进程同时处理同一数据库。不要增加 Uvicorn workers 或直接横向复制；后续扩容需要 PostgreSQL / 队列及推送任务归属分配。

默认最多 10,000 活动和 64 个同时关注的上游品种是容量上限配置，**不是已经完成的承载量测试或服务保证**。同品种由所有用户共享上游订阅。推送并发 16；默认变化报价每 15 秒最多提交一次，未变价格每 60 秒发一次有效源心跳。iOS 和 APNs 决定实际送达，不能承诺每秒刷新。

## 1. 准备

- 一台可访问 Hyperliquid、Apple APNs 和授权股票供应商的 Linux 服务器，安装 Docker Engine 和 Compose。
- API 域名解析到服务器，开放 80 / 443；**不要把 api 容器的 8000 端口发布到公网**。
- Apple Developer 的 Team ID、主 App Bundle ID、APNs Key ID 与 `.p8` 私钥。密钥留在服务器，不进入 App 或 Git 仓库。
- 可选的股票 API key、市场授权和实际延迟信息。未配置不影响合约行情，但股票目录不会出现。

## 2. 配置

在 Server 目录：

```bash
cp .env.example .env
python3 -c "import secrets; print(secrets.token_hex(32))"
```

把生成的值填到 `.env` 的 `TOKEN_ENCRYPTION_KEY`，该值需要持久保存；它加密数据库中的活动 token。修改该密钥会使既有订阅无法解密。填写域名、Bundle ID、Team ID、Key ID 和推送环境。

将 `.p8` 放在 `secrets/AuthKey.p8`。Linux 容器用户 UID 为 10001：确保 secrets 目录和私钥归该 UID 所有，目录权限 700、私钥 400，防止无关账号读取。`.env` 建议权限 600。不要提交这些文件。

Debug 构建对应 `APNS_ENVIRONMENT=development`；TestFlight / App Store 构建对应 `production`。推荐不同域名、独立数据库部署两套服务。

## 3. 启动

```bash
docker compose up -d --build
docker compose logs --tail=100 api
curl https://你的API域名/healthz
curl https://你的API域名/readyz
```

Caddy 自动申请 HTTPS 证书。首次目录发现需要时间。`healthz` 表示进程活着；`readyz` 检查配置与市场目录，不代表 APNs 凭证已经被苹果验证。

只有 `readyz` 的 `backgroundPush` 与 `marketCatalog` 均为 true，客户端才可以创建活动。未配置时返回 503 和明确的状态。

Compose 的 api 仅供同一私有网络中的 Caddy 访问；因此 Uvicorn 信任代理头。若更改网络或直接对公网暴露 api，必须同时收紧可信代理范围，否则注册限流 IP 可被伪造。

## 4. 股票源

- 填 `TWELVE_DATA_API_KEY`。
- 确认持有适用于实际目标市场、数据集及对外展示的权限后，设置 `TWELVE_DATA_EXTERNAL_DISPLAY_LICENSED=true`。这只是运营者的配置声明，不会自动授予数据权利。
- 对已授权的市场填 `TWELVE_DATA_US_DELAY_SECONDS` / `TWELVE_DATA_HK_DELAY_SECONDS`：0 为实时源，900 表示 15 分钟延迟，-1 禁用。按供应商实际授权填写，不能为了去掉“延迟”字样填 0。
- 有对应 WebSocket 权限时设 `TWELVE_DATA_WEBSOCKET_ENABLED=true`。股票流用鉴权请求头，不把密钥写到 URL。
- `STOCK_REQUESTS_PER_MINUTE` 按购买套餐调节，所有股票快照和目录发现共用请求预算；429 进入冷却。REST 用于启动、参考收盘价和断线恢复，流式报价不消耗 REST 轮询额度。

目录来自上游实际 `stocks` 返回值，限定 NASDAQ、NYSE 和 HKEX 及相应原币种。部分市场/API 权限不足时不会创建伪造的代码映射。Twelve Data 的真实账户覆盖、字段和权限仍需上线前联调。

## 5. 持久化与运维

- 数据保存在 `nosce_data` 卷。**不要运行 `docker compose down -v`，否则会删除订阅数据库。**
- 保留数据库、`.env` 的加密密钥及私钥的受控备份。可使用 SQLite online backup API 做一致性备份；不能只复制运行中的主 sqlite 文件而忽略 WAL。
- 配置外部 uptime 检查 `healthz` / `readyz`，收集容器错误日志；公开上线建议加 CDN/WAF，尤其保护匿名设备注册接口。
- 注册按 IP 限流，设备请求按匿名凭证限流，推送订阅有全局容量限制。对高攻击压力或大规模增长，需要进一步接入 App Attest / 风控和横向扩容。
- 不记录 Bearer、APNs token、上游 key 或带密钥的完整 URL。默认关闭访问日志，支持诊断中不包含这些值。
- 活动最长保留 8 小时；无效 token 会清理，设备可主动删除服务数据。没有活跃活动的匿名设备凭证超过 90 天会清理；下次打开 App 自动重新登记。

## 7. 发布前真实验收

1. 用 Mac 跑 CI 同等的 Swift 解码检查和 Release 编译，再签名安装。
2. 分别验证 APNs development 与 production，不能把沙盒成功当成 TestFlight 成功。
3. 开启 BTC 盯盘，确认后台登记成功。切换其他 App、锁屏后对照上游与服务器日志，记录实际延迟。
4. 重启服务器，确认订阅无需手机重新打开即可恢复。
5. 断开上游或停止服务器，确认卡片按 stale-date 过期，而不是续写旧价格；恢复后确认更新。
6. 用户结束/移除活动、token 轮换、APNs 410/429、市场休市和延迟股票报价均应验证。
7. 验证股票真实账户字段、市场覆盖、授权和额度；确认 App 隐私政策/支持页与实际数据处理一致。

Docker 构建、Caddy 的真实证书申请和苹果生产推送尚未在本次环境执行。
